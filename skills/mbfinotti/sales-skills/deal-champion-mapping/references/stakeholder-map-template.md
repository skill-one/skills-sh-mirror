# Stakeholder map template

Fill every field or write the honest gap ("unknown - next action X"). An empty cell is a mapping failure; a stated unknown is deal intelligence.

```
STAKEHOLDER MAP
Account     : <name>            Deal size/segment : <$ / transactional|mid-market|enterprise>
Stage       : <stage>           Date              : <date>       Version : <n>
Methodology : <team's methodology, if any - use its vocabulary in the role column>

STAKEHOLDERS (one row per person, present on calls or not)
| Name | Title | Assigned role | Evidence (tier: what they did/said) | Confidence | Gap unproven | Next action |
|------|-------|---------------|-------------------------------------|------------|--------------|-------------|
|      |       |               |                                     |            |              |             |

CHAMPION TEST LOG
Candidate        : <name>
Asks made        : <capital-costing asks + rung + dates>
Follow-through   : <what actually happened, by when>
Next ask         : <rung 1-4> - <the ask, with its deadline>
Why this rung    : <rung below passed / deleted by RFP or stage / promoting condition met>
Verdict          : champion (Tier-1 proven) | coach (hedged/deferred twice) | untested

ECONOMIC BUYER
Named            : <name + evidence tier> | UNKNOWN
If unknown       : surfacing action - <which role-identifying question, asked of whom>
If access deferred: reading -> countermove <from the deferral table; if no reading is
                   evidenced, run them in that table's order, top row first>

BLOCKER HYPOTHESES (>=1; >=1 for a function not yet on any call)
Rows in the taxonomy's efficiency order; delete the functions this deal has no seat for.
| Function | Person (or "unidentified") | Signal observed | Veto power | Neutralise/co-opt plan | Effort |
|----------|---------------------------|-----------------|------------|------------------------|--------|
|          |                           |                 |            |                        |        |

COVERAGE
Engaged contacts : <n> vs benchmark <~4-7 mid-market / ~10 / 11-17+ enterprise>
Real relationships (not just email addresses): <n>
Single-threaded  : yes/no -> if yes, expansion target: <function + why>

CHAMPION RISK
Redundancy candidate : <name being cultivated> | none (gap)
Executive sponsor    : <name> | none (gap)
Job-change detection : alerting in place | manual | none

REFRESH TRIGGER
Re-walk this map on: stage change | new stakeholder appears | champion job-change
signal | <deal-specific event> - whichever comes first.
```

## B2C household adaptation

Same table, different rows:

- Roles column uses the household DMU vocabulary: initiator, influencer, decider, buyer, user, gatekeeper - plus champion (the selling spouse/partner) and detractor (the skeptical relative or co-signer).
- Delete the blocker functions with no household equivalent: procurement, legal, security, compliance. Keep economic (household budget), political (competing family priority), and incumbent loyalist ("the current kitchen is fine").
- Delete the job-change-detection row; champion risk becomes "what happens if the enthusiastic partner cools off before the decider engages?"
- Evidence tiers, the champion test log, EB naming, confidence rules, and the refresh trigger stay exactly as in B2B.
